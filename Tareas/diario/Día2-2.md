## Bloque A — Matching por nombre (confianza media/baja)

**Motivación:** el matching actual es SHA1 puro. ROMs parcheadas, hacks, dumps no estándar o archivos renombrados no tienen su SHA1 en los DATs y quedan como `unresolved` para siempre, aunque el catálogo tenga un título muy similar.

### A1. Normalizador de títulos para comparación ✓

**Archivo:** `detection/filename_normalizer.py` (ya existe, ampliar)

Crear función `normalize_for_match(name: str) -> str` que:
- Elimina la extensión
- Pasa a minúsculas
- Elimina contenido entre paréntesis y corchetes: `(USA)`, `[!]`, `(Rev 1)`, etc.
- Colapsa espacios y guiones bajos

```python
normalize_for_match("Tetris (World) [!].gb") == "tetris"
normalize_for_match("super_mario_land_(usa).gb") == "super mario land"
```

### A2. Índice de títulos normalizados en `CatalogMatcher` ✓

**Archivo:** `catalog/matcher.py`

Al cargar los DATs, construir adicionalmente un dict:
```python
_title_index: dict[str, list[CatalogEntry]]
# clave: normalize_for_match(entry.title)
```

### A3. Fallback por nombre en `CatalogMatcher.match()` ✓

Extender `match(sha1, filename)` con segundo argumento opcional:

```python
def match(self, sha1: str, filename: str | None = None) -> MatchResult | None:
    # 1. Búsqueda SHA1 exacta → confidence "high"
    # 2. Si no hay hit y filename no es None:
    #    normalize_for_match(filename) → buscar en _title_index
    #    hit único → confidence "medium"
    #    múltiples hits → confidence "low" (devolver el primero, marcar como ambiguo)
    #    sin hit → None
```

`MatchResult` necesita campo `ambiguous: bool = False` para el caso `low`.

### A4. Actualizar CLI `rommgr match` ✓

Pasar `game.original_filename` al llamar a `matcher.match()`.

Añadir línea en el resumen final:
```
Matched (SHA1):   4 101
Matched (nombre): 87
Not found:        15
```

### A5. Tests ✓

**Archivo:** `tests/test_catalog_matcher.py` (ampliar)

- Fallback por nombre cuando SHA1 no existe en DAT
- Normalización ignora región y flags
- Hit único → confidence "medium"
- Múltiples hits → confidence "low", `ambiguous=True`
- Sin hit → `None`

## Bloque C — Calidad y robustez

### C1. `rommgr inspect-assets`

**Motivación:** la biblioteca puede tener thumbnails, videos y XML de EmulationStation. Saber qué assets están presentes y cuáles faltan es útil antes de pasar la colección a la Anbernic.

Nuevo comando que lista:
- Assets detectados por plataforma y tipo (image/video/xml)
- Plataformas sin ningún asset
- Assets huérfanos (sin ROM correspondiente en la BD)

### C2. Validación de sets `.cue`

**Archivo:** nuevo `detection/cue_validator.py`

Función `validate_cue(cue_path: Path) -> list[str]` que:
- Parsea todas las líneas `FILE "nombre.bin" BINARY`
- Comprueba que cada `.bin` referenciado existe junto al `.cue`
- Devuelve lista de errores (vacía si el set está completo)

Integrar en `rommgr scan` como advertencia no bloqueante:
```
[WARN] Metal Gear Solid (Disc 2).cue — falta: MGS_2.bin
```

### C3. `rommgr unresolved --export`

Añadir flag `--export FILE` al comando `unresolved` para guardar la lista en CSV, útil para compartir con herramientas externas o buscar DATs alternativos.

## Bloque D — Documentación y guía Android

### D1. Guía de configuración en la Anbernic RG 556

**Archivo:** `docs/android-sync.md` (nuevo)

Documentar las dos opciones para el lado Android:

**Opción A — Termux + rclone** (más control):
1. Instalar Termux desde F-Droid
2. `pkg install rclone`
3. `rclone config` apuntando al mismo remote que el PC
4. Script de sync ejecutable desde Termux (o con Termux:Boot para autostart)

**Opción B — FolderSync Pro** (más fácil para el usuario):
1. Instalar FolderSync desde Play Store
2. Configurar par de sincronización: `/storage/emulated/0/RetroArch/saves/` ↔ `Dropbox:/RetroArch/saves`
3. Sync automático por WiFi cada X minutos

Incluir rutas típicas de saves y states en RetroArch Android.
