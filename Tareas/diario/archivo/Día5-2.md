## Bloque B — Mejoras en la pestaña Tools

### B1. Descomprimir ZIPs: soporte de carpetas anidadas

- El extractor actual no desciende en subdirectorios para buscar `.zip`
- Cambiar a búsqueda recursiva (`**/*.zip`)
- Al extraer, **respetar la ruta relativa**: un ZIP en `psx/extras/game.zip` se extrae
  en `psx/extras/`, no en la raíz de la biblioteca
- Evitar extraer disc sets (misma lógica que ya existe para CHD)

### B2. Verificar sets multi-disco con el mismo algoritmo que ZIP

- El algoritmo de detección de disc sets ya existe en `multidisc_verifier.py`
- Reutilizarlo en el extractor ZIP: si se detecta que un ZIP forma parte de un set,
  marcarlo para conversión a CHD en lugar de extraer
- Añadir opción "Convertir disc sets a CHD automáticamente tras extracción"

### B3. Informe de biblioteca (panel HTML en Tools)

Nueva sección al final de la pestaña Tools: **"Informe de biblioteca"**.

| Pestaña | Contenido |
|---------|-----------|
| **ZIPs** | Lista de ZIPs procesados / pendientes de extraer; espacio recuperable |

## Bloque C — Cable Sync: deduplicación por SHA1

*(Diseñado en Día 5, implementación pendiente)*

### C1. Backend: `repository.sha1_exists(sha1) -> bool`

```python
def sha1_exists(self, sha1: str) -> bool:
    with self.connect() as conn:
        return conn.execute(
            "SELECT EXISTS(SELECT 1 FROM games WHERE sha1 = ?)", (sha1,)
        ).fetchone()[0]
```

### C2. Backend: filtro en `_handle_cable_sync`

- Cuando `direction == "anbernic_to_pc"` y el flag `skip_duplicates_sha1` está activo:
  - Calcular SHA1 del archivo antes de copiar (reutilizar `hash_calculator`)
  - Si `sha1_exists()` → saltar y contabilizar como "omitido (duplicado)"
- El resultado del job debe mostrar: copiados / omitidos por SHA1 / errores

### C3. UI: checkbox "Omitir ROMs duplicados (comprueba SHA1 en BD)"

- Solo visible cuando la dirección es Anbernic → PC
- Tooltip: "Requiere que la SD card haya sido escaneada previamente desde Overview"

## Bloque D — Ruta de la Anbernic por cable

### D1. Investigar y documentar la ruta correcta

- La ruta `Este equipo\RG556\Ambernic` reportada por el sistema **no es accesible** desde Python
- Opciones a evaluar:
  1. **SD card en lector**: aparece como letra de unidad (`F:\`) → funciona directamente ✅
  2. **MTP (cable USB)**: Windows expone el dispositivo como objeto COM, no como ruta del sistema de archivos;
     se necesitaría `winfsp` + `android-file-transfer` o similar para montarlo como letra de unidad
  3. **Termux SFTP**: exponer la Anbernic como servidor SFTP en la red local → accesible con `rclone sftp`
- Documentar la opción más práctica y actualizar las instrucciones en el panel Cable Sync

### D2. Actualizar instrucciones en el panel Cable Sync

- Añadir nota clara: "La ruta MTP de Windows (Este equipo\RG556) no es compatible"
- Guiar al usuario hacia la opción SD card o Termux SFTP
- Enlace a `Tareas/Guia-Termux-Anbernic.md`
