## Contexto

Al cierre del Día 3 teníamos 200 tests pasando, el frontend completo con todas las
operaciones CLI expuestas, y un análisis de huecos que identificó tres bloqueantes críticos
para el objetivo de la Anbernic: sync de saves, scraping/gamelist.xml y copia de ROMs.

Esta sesión resolvió el bloqueo del sync:

- Se decidió usar **Termux + rclone** en la Anbernic (gratuito, mismo binario que el PC,
  más control que FolderSync).
- Se descubrió que los saves viven **junto a los ROMs** en el mismo árbol de carpetas
  (`E:\Carpetas anbernic\gba\Game.sav` al lado de `Game.gba`), no en una carpeta separada.
- Se adaptó toda la capa de sync al nuevo layout: `saves_dir` → `library_root`.
- Se creó `config.toml` con las rutas reales del proyecto.
- Se creó una guía paso a paso para configurar Termux en la Anbernic.
- Se corrigieron los tests rotos que acumulaba el proyecto desde el Día 3.

Estado al cierre del bloque previo: **200 tests passing**. El sync PC→cloud está operativo.
Falta el lado Android (instalar Termux en la Anbernic y ejecutar la guía).

## Trabajo realizado

### Integración ScreenScraper (`6ab3cfe`)

Nuevo paquete `scraper/` con tres módulos:

| Archivo | Propósito |
|---------|-----------|
| `scraper/screenscraper.py` | Cliente REST ScreenScraper; busca por CRC32/MD5/SHA1; descarga título, año, género, publisher, descripción, URL de portada |
| `scraper/platform_ids.py` | Mapeo plataforma interna → ID numérico de ScreenScraper (~30 plataformas) |
| `scraper/gamelist_writer.py` | Genera `gamelist.xml` por plataforma en el formato EmulationStation; las portadas se guardan en `downloaded_images/` |

El scraping corre como job en background (`_jobs["scrape"]`) con polling igual que scan y match. El progreso se muestra en tiempo real en la barra del frontend.

### Generación de `gamelist.xml`

`gamelist_writer.write_gamelist()` genera un XML por plataforma en `library_root/<platform>/gamelist.xml` con los campos que espera EmulationStation:
```xml
<game>
  <path>./Juego.gba</path>
  <name>Juego</name>
  <desc>...</desc>
  <image>./downloaded_images/Juego.png</image>
  <releasedate>20031201T000000</releasedate>
  <publisher>Nintendo</publisher>
  <genre>Platform</genre>
</game>
```

### Settings tab

Nueva pestaña Settings en el frontend con formulario para editar `config.toml`:
- Campo `library_root`
- Campos `screenscraper_user` y `screenscraper_pass`
- Botón Guardar que escribe el TOML y **recarga la config en memoria** sin reiniciar el servidor

### Quick scan mode

Toggle en la UI de Overview ("Scan rápido — sin hash"). La UI está conectada y manda el flag al endpoint `/api/scan`. La implementación en `rom_scanner.py` quedó pendiente: el toggle existe pero el backend ignora el flag por ahora.

### Rename atómico ROM + saves (`9deaeea`)

Nuevo módulo `renamer/file_renamer.py` con:
```python
rename_rom_with_saves(source_path, target_path, save_extensions) -> RenameOutcome
```
Comportamiento:
- Renombra la ROM primero
- Renombra todos los saves con el mismo stem en el mismo directorio
- Si falla cualquier paso, hace rollback completo de todos los archivos ya renombrados
- Devuelve `RenameOutcome(success, saves_renamed, error)`

### Correcciones de bugs (`f26fee8`, `1423dfa`, `141837a`)

| Bug | Causa raíz | Solución |
|-----|-----------|----------|
| ~1800 falsos conflictos en Plan (solo-mayúsculas) | `target.exists()` devuelve `True` en Windows para renames de solo capitalización (NTFS insensible a mayúsculas) | `_same_file(a, b)` con `Path.samefile()` en `operation_planner.py` |
| Credenciales ScreenScraper no aplicaban hasta reiniciar | Config cargada solo al arrancar el servidor | `_handle_save_config()` recarga el objeto config en memoria tras escribir el TOML |
| ScreenScraper devuelve HTTP 403 | Parámetros vacíos `devid=""` y `devpassword=""` enviados en la URL | Solo añadir esos parámetros a la URL cuando no estén vacíos |
| Sin feedback durante conversión CHD | No había progress bar para ese job | Añadida barra de progreso CHD igual que las de scan y match |
| Archivos "Unknown" sin explicación en la UI | Tab Assets no explicaba qué son los desconocidos | Añadido texto explicativo en el panel Unknown |
| Botón "Eliminar duplicados" solo permitía borrar uno a uno | No había acción masiva | Añadido botón "Eliminar todos los duplicados" con confirmación |
