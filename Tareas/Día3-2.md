# ROM Manager Local — Día 3-2

## Contexto

Al cierre del Día 3 teníamos 200 tests pasando, el frontend completo con todas las
operaciones CLI expuestas, y un análisis de huecos que identificó tres bloqueantes críticos
para el objetivo de la Anbernic: sync de saves, scraping/gamelist.xml y copia de ROMs.

Esta sesión resolvió el bloqueo del sync:

- Se decidió usar **Termux + rclone** en la Anbernic (gratuito, mismo binario que el PC,
  más control que FolderSync).
- Se descubrió que los saves viven **junto a los ROMs** en el mismo árbol de carpetas
  (`E:\Carpetas anbernic\gba\Game.sav` al lado de `Game.gba`), no en una carpeta separada.
- Se adaptó toda la capa de sync al nuevo layout: `saves_dir` → `library_root`.
- Se creó `config.toml` con las rutas reales del proyecto.
- Se crearon una guía paso a paso para configurar Termux en la Anbernic.
- Se corrigieron los tests rotos que acumulaba el proyecto desde el Día 3.

Estado al cierre: **200 tests passing**. El sync PC→cloud está operativo.
Falta el lado Android (instalar Termux en la Anbernic y ejecutar la guía).

## Objetivos del día

1. **Scraping con ScreenScraper** — llamar a la API por cada ROM usando CRC32/MD5/SHA1
   que ya tenemos en la BD; descargar título, año, género, publisher, descripción, portada.

2. **Generación de `gamelist.xml`** — producir un XML por plataforma en el formato que
   espera EmulationStation (el frontend de la Anbernic). Sin esto, la consola muestra solo
   una lista de texto plano.

3. **Settings tab en el frontend** — formulario para editar `config.toml` desde la UI
   (mínimo: `library_root`, `rclone_remote`). Necesario para que un usuario normal
   pueda configurar el sync sin editar TOML a mano.

4. **Quick scan mode** *(si da tiempo)* — modo `--quick` que indexa nombre + tamaño +
   mtime sin calcular hashes. Para librerías grandes (ISOs de PS2/Wii) el scan inicial
   puede tardar horas; el modo rápido permite navegar la biblioteca de forma inmediata.
